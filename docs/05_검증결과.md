## 4. 해석 — 이 숫자가 말하는 것

### 재현율 100%는 자랑이 아니다

규칙 필터는 결정론이다. 같은 입력에 항상 같은 결과를 내므로 정답 리스트를
정확히 적었다면 100%가 나오는 것이 정상이다.

이 수치가 증명하는 것은 정확도가 아니라 **회귀 안전성**이다.

- 규칙이 35개 시나리오에서 정의대로 동작한다
- §7.3 오답 7종을 한 건도 내지 않는다
- 코드를 고쳤을 때 이 성질이 깨지면 `npm test`가 즉시 실패한다

### 15.5%가 실제 수치다

확률론이 개입하는 유일한 지점은 2단계 LLM의 문장이다. 모델은 97건 중 15건에서
판단·권유 표현을 썼다. 6~7번에 한 번꼴이다.

**그 15건이 사용자에게 한 건도 닿지 않았다.** 이것이 "LLM 래퍼가 아니다"의
근거다. 래퍼라면 모델 출력이 그대로 화면에 나가고, 6~7번에 한 번씩 법률
조언에 해당하는 문장이 노출된다.

### 구조가 만드는 차이

```
규칙 필터(결정론) → LLM 재평가 → guard 필터
```

- LLM은 후보를 **새로 만들 수 없다.** 모르는 candidate_id는 버려진다
- LLM이 "관련 없다"고 해도 항목은 **지워지지 않는다.** 규칙 엔진이 이미
  조건을 확인했기 때문이다
- guard에 걸린 항목은 사라지지 않고 결정론 문안으로 **되돌아간다**
- `requires_expert` 항목은 LLM에 보내지도 않는다. 고정 템플릿만 나간다

기한·법정상속분·소액 간소화 판정에는 LLM이 아예 관여하지 않는다.

### 예상 질문 대응

**"결국 LLM 래퍼 아닌가요?"**
기한과 법정상속분에는 LLM이 관여하지 않습니다. 누락 탐지에서도 LLM은 항목을
만들거나 지우지 못하고 문장만 다듬습니다. 그 문장의 15.5%가 차단됐습니다.

**"재현율 100%는 과적합 아닌가요?"**
정답 리스트를 코드 실행 결과가 아니라 규정 문서를 읽고 손으로 적었습니다.
그리고 결정론 엔진이라 100%가 정상입니다. 이 수치는 정확도가 아니라 회귀
안전성을 봅니다.

**"규정이 바뀌면요?"**
`data/` 하위 JSON 교체만으로 반영됩니다. 코드에 기관별 분기가 없다는 것을
테스트로 강제하고 있습니다.
