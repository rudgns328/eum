## 4. 해석 — 이 숫자가 말하는 것

### 재현율 100%는 자랑이 아니다

규칙 필터는 결정론이다. 같은 입력에 항상 같은 결과를 내므로 정답 리스트를
정확히 적었다면 100%가 나오는 것이 정상이다.

이 수치가 증명하는 것은 정확도가 아니라 **회귀 안전성**이다.

- 규칙이 35개 시나리오에서 정의대로 동작한다
- §7.3 오답 7종을 한 건도 내지 않는다
- 코드를 고쳤을 때 이 성질이 깨지면 `npm test`가 즉시 실패한다

### 15.5%가 실제 수치다

확률론이 개입하는 유일한 지점은 2단계 LLM의 문장이다. 모델은 97건 중 15건에서
판단·권유 표현을 썼다. 6~7번에 한 번꼴이다.

**그 15건이 사용자에게 한 건도 닿지 않았다.** 이것이 "LLM 래퍼가 아니다"의
근거다. 래퍼라면 모델 출력이 그대로 화면에 나가고, 6~7번에 한 번씩 법률
조언에 해당하는 문장이 노출된다.

### 구조가 만드는 차이

```
규칙 필터(결정론) → LLM 재평가 → guard 필터
```

- LLM은 후보를 **새로 만들 수 없다.** 모르는 candidate_id는 버려진다
- LLM이 "관련 없다"고 해도 항목은 **지워지지 않는다.** 규칙 엔진이 이미
  조건을 확인했기 때문이다
- guard에 걸린 항목은 사라지지 않고 결정론 문안으로 **되돌아간다**
- `requires_expert` 항목은 LLM에 보내지도 않는다. 고정 템플릿만 나간다

기한·법정상속분·소액 간소화 판정에는 LLM이 아예 관여하지 않는다.

### 재현 방법

```bash
PARSE_SAMPLES_DIR=<샘플 경로> npm run measure:parse
```

실 Anthropic API를 호출한다. `npm test`에는 포함하지 않는다.

### 샘플 (4건)

| 파일 | 문서 | 출처 |
|---|---|---|
| `family_01` | 가족관계증명서(상세) | 대법원 전자가족관계등록시스템 **테스트 프린트** |
| `fss_01` | 금융거래 조회결과 · 선명 | 합성 |
| `fss_02` | 금융거래 조회결과 · 저해상도 + 흐림 | 합성 |
| `fss_03` | 금융거래 조회결과 · 금액 칸 일부 가림 | 합성 |

조회결과는 개인별 결과라 정부24·금감원 모두 견본을 공개하지 않는다. 그래서
합성 샘플로 만들었고, 문서에 「테스트용 합성 샘플」 워터마크를 넣었다.

**샘플 이미지는 리포지토리에 두지 않는다.** 개인정보가 없더라도 저장소에 둘
이유가 없다(`docs/test_docs/`는 `.gitignore` 대상).

### 정답지

시나리오 35건과 같은 원칙이다 — **모델 출력을 베끼지 않고 문서를 보고 손으로
적었다.** 채점 기준은 아래와 같고, 한 항목이라도 어긋나면 오답으로 센다.

| 문서 | 맞아야 하는 것 |
|---|---|
| 가족관계증명서 | 관계 · 생존 여부 · 미성년 여부. 이름이 마스킹되지 않으면 오답 |
| 조회결과 | 기관명 · 업권 · 금액. 기관명은 표기 흔들림 허용 |

정답에 없는 항목을 만들어내면 따로 센다.

### 결과 (2026-09-06)

```
 family_01.png   6/6  100%   conf 0.88
 fss_01.png      6/6  100%   conf 0.95
 fss_02.png      6/6  100%   conf 0.93
 fss_03.png      6/6  100%   conf 0.85

 문서            4건
 정답 항목       24건
 정확 추출       24건
 없는 항목 생성   0건

 파싱 정확도     100.0%   (목표 90% 이상)
```

### 회귀를 한 번 냈다가 되돌렸다

항목별 확신도를 붙이면서 프롬프트에 "그 한 줄만 보고 판단합니다"를 넣었더니
정확도가 79.2%로 떨어졌다. 모델이 문서 전체 맥락을 끊고, 사망 기재가 없는
사람 전원을 `alive: null`로 돌렸다.

확신도는 "얼마나 또렷하게 읽었는지"만 나타내고 값 자체는 문서를 함께 보고
판단하라고 고치자 100%로 돌아왔다. 스키마를 건드릴 때는 반드시 재측정해야
한다는 사례로 남긴다.

### 측정이 잡아낸 결함 1건

첫 측정에서 95.8%(23/24)가 나왔고, 틀린 한 건이 실제 결함이었다.

> `자녀 김상민(2003년생)`을 **미성년으로 판정**했다.

프롬프트가 기준일을 주지 않아, 모델이 문서에 찍힌 발급일(2020-11-04)을
기준으로 삼은 것으로 보인다. 그 시점에는 17세였으므로 모델 입장에서는 합리적인
추론이었다. `is_minor`는 특별대리인 선임 판정(민법 제921조)과 삼성생명
친권확인서 판정에 쓰이므로 그대로 두면 안 되는 오류였다.

지시문에 기준일을 명시하도록 고친 뒤 100%가 되었다.

**이 항목이 측정의 값어치를 보여준다.** 숫자를 얻으려고 한 측정에서 정작
얻은 것은 결함 하나였다.

### 모르는 것을 모른다고 한다

`fss_03`은 금액 칸 두 개가 가려진 문서다. 모델은 그 두 칸을 **추측해 채우지
않고 `null`로 두었고**, confidence를 0.95에서 0.86으로 스스로 낮췄다.
"확인되지 않는 값은 추측하지 말고 null로 둔다"는 지시가 실제로 동작한다.

**"결국 LLM 래퍼 아닌가요?"**

테스트로 강제하고 있습니다.
