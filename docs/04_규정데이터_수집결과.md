## 0. 이 문서를 읽는 방법

- **모든 값에 출처와 확인 방법이 붙어 있다.** 공개 페이지에서 확인한 값과 통화로만 확인한 값을 구분해 표기했다. 구분이 없는 값은 사용하지 말 것.
- **추정으로 채운 값은 없다.** 확인되지 않은 필드는 `null` + `verified: false`로 남겼다. CLAUDE.md 작업 방식 항목의 요구사항이다.
- **`unresolved_fields`가 있는 기관은 데모 시나리오에서 제외한다.** 현재 카카오뱅크 1곳이 해당한다.

## 1. 기관별 델타 — 핵심 비교표

### 1.1 소액 간소화 기준

| 기관 | 1구간 | 2구간 | 산정 기준 | 동의 방식 |
|---|---|---|---|---|
| KB국민은행 | 300만 / 1인 | **1,000만** / 3인↑ ½ | 원금 | 동의 (인원 기준) |
| 신한은행 | 300만 / 1인 | 500만 / 3인↑ **2/3** | 원금 | **실물 방문** |
| 카카오뱅크 | 300만 / 1인 | 500만 / 3인↑ ½ | 원금 | 동의 + 위임 의사 |
| 하나은행 | **100만** / 1인 | 없음 | 원금 | 동의 (1인) |
| 유안타증권 | 300만 / 1인 | **없음** | **평가액 · 신청일** | 동의 |
| 삼성생명 | — | — | 청구금액 | 축이 다름 (§1.2) |

**읽는 법 세 가지.**

1구간 300만원은 KB·신한·카카오·유안타 4곳이 일치한다. 금감원 표준의 영향으로 보이며, 이것이 공통 베이스다. 2구간부터 갈라진다.

**최대 격차는 10배다.** 하나은행 100만원과 KB국민은행 1,000만원. 같은 500만원 예금이라도 KB에서는 상속인 3명 중 2명 동의로 인출되고, 하나에서는 전원 절차를 밟아야 한다.

**신한만 "동의"가 아니라 "방문"이다.** 통화에서 확정했다 — 상속인의 2/3 이상이 영업점에 **실물 신분증을 지참하고 직접 방문**해야 하며 위임장으로 대체할 수 없다. 3형제 중 2명이 실제로 지점에 가야 한다는 뜻이라 체감 난이도가 다르다. 엔진에서 `consent_type: "physical_visit"`로 분기해야 한다.

### 1.2 소액 간소화의 "축"이 업권마다 다르다

| 업권 | 금액 기준이 결정하는 것 | `simplification_type` |
|---|---|---|
| 은행·증권 | 누구의 동의가 필요한가 | `consent_relaxation` |
| 보험 | 원본이냐 사본이냐, 어느 채널로 접수하느냐 | `submission_channel` |

삼성생명의 1,000만원은 "상속인 동의를 덜 받아도 된다"가 아니라 "사본 접수가 된다 / 안 된다"를 가른다. 같은 이름의 필드로 묶으면 로직이 틀린다. **스키마에 `simplification_type` 필드를 추가했다.**

### 1.3 소액 간소화의 실제 효과 — 서식으로 확정된 유일한 사례

유안타증권은 일반 경로와 소액 경로의 서식이 분리되어 있어 무엇이 면제되는지가 첨부 목록으로 확정된다.

| | 일반 (상속계좌 명의변경/지급 요청서) | 소액 (소액 상속재산 지급요청서) |
|---|---|---|
| 첨부 1 | 피상속인 기본증명서 1부 | 피상속인 기본증명서 1부 |
| 첨부 2 | 피상속인 가족관계증명서 1부 | 피상속인 가족관계증명서 1부 |
| 첨부 3 | **상속인들(대표 포함) 인감증명서 각 1부** | 신청인 신분증 사본 1부 |
| 첨부 4 | **상속인들 대표 주민등록증 사본 1부** | — |

상속인 5명이면 인감증명서 5장이 통째로 사라진다.

나머지 두 기관도 통화로 같은 취지를 확인했다.

| 기관 | 소액 경로에서 면제되는 것 |
|---|---|
| KB국민은행 | 미내점 상속인의 위임장·인감증명서. 대표 상속인 서류 + 피상속인 서류만으로 신청 |
| 하나은행 | 미내점 상속인의 위임장·인감증명서. 상속인 측 서류는 방문자 신분증만 |
| 유안타증권 | 미내점 상속인의 인감증명서(N장) + 대표 주민등록증 사본 |

**세 기관 모두 면제 대상은 "상속인 측 서류"뿐이다.** 피상속인 서류(가족관계증명서·기본증명서)는 소액 여부와 무관하게 유지된다. 하나은행에 재확인하여 확정했다 — 소액이어도 피상속인의 가족관계증명서는 필요하다.

엔진에서는 `target: "피상속인"`인 서류에 간소화 규칙을 적용하지 않도록 분기해야 한다. `condition: "unless_simplified"`는 상속인 측 서류에만 붙인다.

## 2. 안내문과 실무의 불일치 — 이 프로젝트의 핵심 근거

수집 6개 기관 중 **4곳에서 공개 안내와 실제 답변이 어긋났다.** 방향이 양쪽 모두 존재한다는 점이 중요하다. 단순히 "은행이 불친절하다"가 아니라 "공개 정보로는 판단할 수 없다"는 구조적 문제다.

| 기관 | 유형 | 공개 안내 | 실제 확인 | 영향 |
|---|---|---|---|---|
| 하나은행 | **비공개** | 소액 금액 기준 **없음** | 100만원 이하 | 홈페이지만으로 소액 가능 여부 판단 불가 |
| 하나은행 | 안내가 더 엄격 | 상속인 각자의 가족관계증명서·제적등본 | 피상속인 서류만 필요 | 불필요한 서류 발급 |
| 삼성생명 | **오독 유발** | 1,000만원 이하 사본접수 가능 (사망 조건부) | 사망보험금은 방문만 | 비대면 가능으로 오해 |
| 유안타증권 | 안내가 더 엄격 | 협의분할 = 법원 재산분할결정문 | 상속인 작성 협의서도 인정 | 불필요한 법원 절차 오인 |
| 신한은행 | 안내 없음 | 미성년자·'07년 이전 사망은 "고객센터 문의" | 구체적 서류 목록 확보 | 표준 플로우 밖 케이스는 공개 안내 부재 |
| 카카오뱅크 | **접근 차단** | "고객센터로 문의" 반복 | 사망 발생 후에만 상담 가능 | 사전 준비 구조적 불가 |

각 기관 JSON의 `discrepancies[]` 배열에 동일 내용이 구조화되어 있다.

**자사 문서 간 상충 1건 — 해소됨.** 유안타증권은 안내 페이지가 "내점 상속인 불필요"라고 적었으나 상속계좌 명의변경/지급 요청서 첨부 3번은 "상속인들(**상속인 대표 포함**) 인감증명서 각 1부"로 기재되어 있었다. 통화 결과 **안내 페이지가 맞다** — 내점 상속인은 인감증명서가 불필요하고, 미내점 상속인만 1인당 1부다. 본인서명사실확인서로 대체 가능하다. 서식 첨부 문구는 전원 미내점을 전제로 한 표현으로 보인다. `resolved: true`.

서식만 보고 준비하면 불필요한 인감증명서를 발급하게 되므로, **서류 합산 기능은 안내 페이지 기준(미내점 인원수 × 1부)으로 계산해야 한다.**

## 3. 공통 표준 레이어 — `standard.json`

금감원 상속인 금융거래조회 서비스는 기관 델타가 아니라 전 금융권 공통이다. 신한은행이 배포하는 금감원 서식 원문에서 확보했다.

### 3.1 조회 서비스가 만드는 함정 — 최우선 구현 대상

> 조회 신청 사실을 통보받은 금융회사는 통상 해당 계좌에 임의로 거래정지 조치를 취하며, 입출금·자동이체가 제한될 수 있다. 이후 예금지급은 원칙적으로 **상속인 전원의 청구**에 의하여 해당 금융기관에서만 지급이 가능하다.
> — 금융감독원 상속인 금융거래조회서비스 안내문

**소액이라 1인 단독으로 인출할 수 있었던 경로가, 조회를 먼저 신청하면 전원 청구로 바뀔 수 있다.** 순서가 결과를 바꾸는 유일한 구조적 함정이고, 어느 기관 안내에도 이 순서에 대한 조언은 없다.

`deadlines_patch.json`의 `time_traps[0]`에 `trap_id: "query_freezes_account"`로 정의했다.

**출력 시 주의.** CLAUDE.md 절대규칙 3에 따라 "먼저 인출하십시오" 같은 권유 표현은 금지된다. 사실 관계만 서술하고 판단은 사용자에게 남긴다.

```
조회 신청 시 계좌 지급정지가 걸릴 수 있으며,
이후 지급은 상속인 전원 청구가 원칙입니다.
(출처: 금융감독원, 2026-08-14)
```

### 3.2 협회별 조회 소요기간 — 기존 "20영업일" 대체

설계서 2.3의 `fss_financial_query: business_days 20`은 추정치였다. 공식 안내문에 협회별 표가 존재한다.

| 구간 | 협회 | 일수 |
|---|---|---|
| 최장 | 여신금융협회, 저축은행중앙회 | 15~20 |
| 중간 | 은행연합회, 신용정보원, 신협, 새마을금고, 산림조합, 예탁결제원 | 10~15 |
| — | 금융투자협회, 우체국 | 7~10 |
| — | 한국대부금융협회 | 7~14 |
| — | 생명보험협회 | 6~10 |
| 최단 | 손해보험협회, 예금보험공사 | 3~7 / 3~10 |

카드·저축은행이 가장 느리다. 최대값 20일은 기존 추정과 일치하나, **협회별로 최대 3배 차이가 나므로 "어느 협회 결과를 기다리는가"에 따라 안내가 달라져야 한다.**

**주의 — 단위 모호.** 원문은 "예상소요기간"으로만 표기하고 영업일/달력일을 구분하지 않는다. 엔진은 보수적으로 영업일로 계산하되, UI에는 원문 표현("기관 안내 기준 15~20일")을 유지할 것. 원문에 "전산사정 등에 따라 초과될 수 있다"고 명시되어 있다.

| 미성년자 신청 | 만 14세 이상 본인 또는 법정대리인 / 만 14세 미만 법정대리인만 |
| 상조 가입 확인 | 성명·생년월일·휴대폰번호 3개 모두 일치 시에만 |

**미성년자 기준이 두 개다.** 금감원 조회는 만 14세, 삼성생명 친권확인서는 만 19세(민법 제4조)다. 엔진에서 혼동하지 말 것.

## 4. 기한 규정 변경 사항

`deadlines_patch.json` 참조. 기존 항목(`renunciation`, `inheritance_tax`, `acquisition_tax`, `safe_inheritance`, `fss_result_expiry`)은 변경 없다.

### 4.1 신규 추가 — 보험금 청구권 소멸시효

```
deadline_id: insurance_claim_prescription
base: death_date (보험사고 발생일)
offset_months: 36
legal_basis: 상법 제662조
severity: high
irreversible: true
applies_if: has_insurance
```

수집 6개 기관 중 **유일하게 권리 자체가 소멸하는 기한**이다. 은행의 3개월은 "이 서류는 못 쓴다"는 입구 제한이지만, 보험의 3년은 "청구권이 없어진다"는 출구 제한이다.

**정렬 주의.** 3년은 기존 기한 중 가장 길어 D-day가 매우 크다. 기한순으로만 정렬하면 대시보드 최하단으로 밀려 존재감이 사라진다. `severity` 우선 정렬 후 기한순으로 처리할 것.

### 4.2 신규 추가 — 기관별 지급 소요

KB·하나·유안타 세 기관이 **업권이 다른데 답변이 거의 동일**했다. 실무 관행이 수렴한 것으로 보인다.

> 소액 상속이거나 단순 예금인 경우 당일 지급도 가능. 고액 상속이거나 상황에 따라 영업일 기준 2~5일.

신한은 5영업일(구분 없음), 삼성생명은 3영업일(조사 필요 시 10영업일)이다. 삼성생명만 공식 문서에 기재되어 있고, 나머지는 **어느 홈페이지에도 없다.**

**서비스 설계 연결.** 소액 경로를 타면 당일, 놓치면 2~5일 + 서류 재발급 왕복이다. 특히 유안타는 평가액이 신청일 기준이라 "하루 늦으면 당일 지급이 2~5일로 바뀔 수 있다"는 연결이 성립한다.

2. (1번 '예'인 경우) 다른 공동상속인들과 상속재산분할에 대한 협의를 하였습니까? → 협의 결과 또는 미협의 사유 기재
3. 신청인 앞으로 명의변경하거나 단독 지급받는 것에 대해 다른 상속인들이 이의를 제기하거나 분쟁이 발생할 가능성이 있습니까? → 구체적 내용 기재

**3번에 "예"로 체크하면 소액 간소화 절차가 즉시 반려된다** (통화 확인). 허위 기재 시 사기·업무방해로 처벌될 수 있다는 경고도 서식에 굵게 명시되어 있다.

KB·신한이 "분쟁이 예상되는 경우 불가할 수 있음"으로 모호하게 처리한 조건을, 유안타는 서면 질문으로 구조화했다. **누락 탐지 규칙이 아니라 서비스의 사전 진단 UI 문항으로 그대로 쓸 수 있다.**

## 6. 스키마 변경 요구사항 (설계서 2.1 대비)

수집 결과 아래 필드가 필요해졌다. 각 기관 JSON에 이미 반영되어 있다.

### 6.1 신규 필드

| 필드 | 값 | 사유 |
|---|---|---|
| `verification` (객체) | `{level, source_confirmed_at, call_verified_at, call_target, note}` | 기존 `verified_at` + `verification_level` 단일 필드로는 원문 확인일과 통화 확인일을 분리할 수 없음 |
| `simplification_type` | `consent_relaxation` \| `submission_channel` | §1.2 — 업권마다 축이 다름 |
| `amount_basis` | `principal` \| `valuation` \| `claim_amount` | 증권은 평가액, 보험은 청구금액 |
| `valuation_date_basis` | `application_date` | 증권 전용. 평가 시점 |
| `simplification_rules[].effect` | 문자열 | 무엇이 면제되는지. 기존 스키마에는 `description`만 있었음 |
| `simplification_rules[].consent_type` | `consent` \| `physical_visit` \| `consent_and_delegation` | 신한 2/3는 방문이 필수 |
| `simplification_rules[].consent_basis` | `headcount` \| `share` | KB 통화로 인원 기준 확정 |
| `processing_days` (객체) | `{simplified, standard_min, standard_max, unit}` | 소액/일반 분기 |
| `min_visiting_heirs` | 정수 | 비대면 위임장이 있어도 최소 내점 인원이 존재 |
| `discrepancies[]` | 배열 | 안내문 vs 실무 불일치 기록. §2 |
| `call_log[]` | 배열 | 통화 원문 Q&A. 재검증 시 근거 |
| `unresolved_fields[]` | 배열 | 미확인 필드 목록. UI "확인 중" 배지 트리거 |

### 6.2 업권별 확장 필드

**증권 (`type: "securities"`)**
```
securities_handling: {
  account_types, deposit_method, securities_method,
  account_opening_required, liquidation_allowed
}
```
`account_opening_required: true` — 증권을 출고받으려면 상속인이 그 증권사에 계좌를 개설해야 한다. 은행 예금에는 없는 부담이며, 상속인 3명이면 3명 모두 필요할 수 있다.

**보험 (`type: "insurance"`)**
```
beneficiary_rule: {
  is_branch_point: true,
  designated: {...},
  undesignated: {...}
}
prescription: { years: 3, base, legal_basis, scope }
```
수익자 지정 여부가 절차 전체를 가른다. 지정되어 있으면 수익자 고유재산이라 상속관계 확인서류도, 다른 상속인 동의도 필요 없다.

### 6.3 케이스 모델 변경 (설계서 2.4)

`assets[]`에 필드 추가가 필요하다.

```json
{
  "institution_id": "samsung_life",
  "type": "insurance",
  "beneficiary_designated": true,
  "is_group_insurance": false,
  "death_type": "non_occupational"
}
```
```json
{
  "institution_id": "yuanta_sec",
  "type": "securities",
  "deposit_amount": 1200000,
  "securities_valuation": 1900000,
  "valuation_date": "2026-08-21"
}
```

증권은 예탁금과 증권을 분리해야 한다. 유안타 서식이 두 칸으로 나뉘어 있고, 소액 판정은 합계 평가액 기준이다.

### 6.4 `document_condition` enum 정리

수집 결과 실제로 나타난 조건들이다.

```
always | optional | unless_simplified
if_non_visiting_heir | if_heirs_unclear | if_basic_cert_unavailable
if_death_before_2008 | if_death_after_2008
if_minor_heir | if_ward_heir | if_overseas_heir
if_will | if_agreement_division | if_renunciation
if_agent_applies | if_agent_claims | if_postal_request | if_visit
if_beneficiary_undesignated | if_multiple_heirs_and_undesignated
```

**`if_heirs_unclear`(제적등본) 트리거는 KB·신한·유안타 3곳이 사실상 동일하다.** 코드로 떨어뜨릴 수 있다.

1. 청구인이 3·4순위 상속인인 경우 (신한: 3순위 형제·자매 이상)
2. 대습상속 등으로 가족관계증명서에 상속인 전원이 나타나지 않는 경우
3. 피상속인이 2008년 이전 사망한 경우 (신한: 2007.12.31 이전으로 명시)

KB 안내에 근거가 있다 — 가족관계증명서로는 피상속인 기준 부모·배우자·자녀(1·2순위)까지만 확인 가능하다.

## 7. 테스트 시나리오 반영 사항 (설계서 8장)

수집 결과 정답 리스트에 반드시 포함해야 하는 항목이다.

### 7.1 금액 경계값

`300만` 1구간 경계는 4개 기관 공통이므로 반드시 테스트한다. 추가로 기관별 2구간 경계가 다르다.

| 테스트 금액 | KB | 신한 | 카카오 | 하나 | 유안타 |
|---|---|---|---|---|---|
| 90만 | 1인 | 1인 | 1인 | **소액 1인** | 1인 |
| 250만 | 1인 | 1인 | 1인 | **일반** | 1인 |
| 400만 | 3인↑½ | 3인↑2/3방문 | 3인↑½ | 일반 | **일반** |
| 700만 | 3인↑½ | **일반** | **일반** | 일반 | 일반 |
| 1,200만 | **일반** | 일반 | 일반 | 일반 | 일반 |

**동일 금액·동일 상속인 구성인데 기관마다 결과가 다르다는 것이 이 표의 핵심이다.** 400만원 / 상속인 3명 케이스는 5개 기관이 3가지 다른 답을 낸다.

### 7.2 필수 시나리오 추가

| # | 조건 | 정답 알림 |
|---|---|---|
| A | 예금 280만(KB) + 조회 미신청 | 소액 1인 청구 가능 / 조회 시 지급정지 가능성 고지 |
| B | 증권 평가액 295만(유안타) | 소액 가능 / 신청일 기준이라 변동 가능 고지 |
| C | 배우자 + 미성년 자녀 2, 협의분할 | 특별대리인 선임 필요(민법 921조), `requires_expert: true` |
| D | 신한 예금 450만, 상속인 3명 | 2/3 이상 **실물 방문** 필요. 위임장 대체 불가 |
| E | 보험(수익자 지정) + 보험(미지정) | 지정 건은 상속관계 서류 불요, 미지정 건은 필요 |
| F | 사망 2년 10개월 경과 + 보험 미청구 | 소멸시효 D-60 경고 |
| G | 하나 예금 250만 | 소액 아님. 100만원 기준 적용 |
| H | 카카오 자산 포함 | "확인 중" 배지. 데모 시나리오 제외 |

시나리오 C는 대습상속과 함께 가장 복잡한 케이스이므로 `requires_expert` 템플릿 출력 검증에 사용한다.

### 7.3 오답 처리 대상

- 하나은행에 300만원 기준을 적용하는 것 (100만원이 맞음)
- 신한 2/3 요건을 위임장으로 충족 가능하다고 안내하는 것
- 유안타 300만원 초과 건에 2구간 완화를 적용하는 것 (존재하지 않음)
- 삼성생명 사망보험금을 비대면 청구 가능하다고 안내하는 것
- 카카오뱅크 미확인 필드를 다른 은행 값으로 추정해 채우는 것
- 유안타증권에서 내점 상속인에게도 인감증명서를 요구하는 것 (미내점 상속인만 해당)
- 소액 간소화 적용 시 피상속인의 가족관계증명서·기본증명서까지 면제하는 것 (상속인 측 서류만 면제)

## 8. 미확인 항목 — 임의로 채우지 말 것

CLAUDE.md 작업 방식 항목에 따라 `null` + `verified: false`로 남겼다.

| 기관 | 미확인 필드 | 사유 |
|---|---|---|
| 카카오뱅크 | 서류 유효기간, 비대면 채널, 소액 면제 서류, 처리기간, 내점 요건, 위임장 양식 위치 | 기관 정책상 통화 불가 |

| 유안타증권 | 매도 후 현금 수령 가능 여부, 서류 보완 "소정의 기간" | 통화에서 미질의 |

## 10. 개발 착수 시 확인할 것

1. **`CLAUDE.md`의 "데이터 현재 상태" 섹션을 갱신해야 한다.** 현재 "kb_bank.json — 발췌 기반 초안, `unverified`"로 기재되어 있으나, 실제로는 전문 확보 + 통화 검증이 완료되어 `call_verified`다. 카카오뱅크를 제외한 5곳이 동일하다.

2. **Phase 2에서 로더는 `unresolved_fields[]`를 읽어 UI 배지를 자동 생성하도록 만든다.** 기관별로 하드코딩하지 말 것.

3. **Phase 1 기한 엔진에 3년(소멸시효)을 포함한다.** 영업일 계산은 2026년 공휴일 기준으로 하되, 협회별 소요기간의 단위 모호성 때문에 `unit_ambiguous` 플래그가 있는 값은 UI에서 원문 표현을 유지한다.

4. **시간 함정 8건은 Phase 5가 아니라 Phase 1~2에서 규칙으로 구현 가능하다.** 전부 결정론적 조건이며 LLM이 필요 없다. `query_freezes_account`와 `securities_valuation_drift`가 서비스의 차별점이므로 우선 구현한다.
