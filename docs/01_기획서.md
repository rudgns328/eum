# 이음(EUM) — 상속 금융절차 내비게이터

**2026 금융 AI Challenge 기획서**

> 서비스명은 가안입니다. 대안: 상속길잡이, 다음절차, 잇다

---

## 1. 한 줄 정의

상속인이 3개월 안에 끝내야 하는 금융 절차를, 기한과 서류 단위로 대신 관리해주는 서비스.

---

## 2. 문제 정의

### 2.1 상속세를 내는 6%에게는 233명의 전문가가 있습니다. 나머지 94%에게는 아무도 없습니다

국세청 상속세 결정 현황(2024년 귀속분, 2025년 공개)에 따르면 피상속인 35만 8,979명 중 상속세 과세 대상자는 2만 1,193명입니다. **약 5.9%** — 본 문서에서는 '6%'로 통칭합니다. (발표 전 2025년 귀속분 공개 여부를 확인해 최신 수치로 교체)

'233명'은 상속 플랫폼 도와줘상속이 내세우는 검수 전문가(국세청 출신 세무사·변호사) 수로, 유상 수임 시장의 밀도를 보여주는 상징적 수치입니다.

시장의 상속 서비스(세무법인, 법무법인, 상속 플랫폼)는 사실상 전부 이 과세 구간 또는 분쟁·소송 수요층을 대상으로 합니다. 수임료가 발생하는 구간이기 때문입니다.

그러나 절차의 복잡성은 자산 규모와 무관합니다. 3천만 원을 상속받는 사람도 은행 10곳을 똑같이 돌아야 하고, 3개월 기한을 똑같이 지켜야 합니다.

**수수료를 낼 수 없어서 방치된 94%가 이 서비스의 대상입니다.**

### 2.2 정부는 "찾기"에서 끝납니다

금융감독원 상속인 금융거래 조회 서비스는 안내문에 이렇게 명시합니다.

> "상세 거래내역, 잔액 등은 해당 금융회사에 직접 방문하여 확인하셔야 합니다."

안심상속 원스톱서비스도 동일합니다. 제공 자료는 참고용이며, 법적 증빙은 각 기관에서 별도 발급받아야 합니다.

| 구분 | 정부 서비스 | 이음 |
|---|---|---|
| 답하는 질문 | 무엇이 어디에 있나 | 그래서 뭘 언제까지 하나 |
| 산출물 | 기관명 + 금액 목록 | 개인 맞춤 실행 타임라인 |
| 끝나는 지점 | "직접 방문하세요" | 방문 전 준비 완료 |
| 기한 안내 | 없음 | 핵심 기능 |

### 2.3 제도가 만든 시간 함정

이것이 이 서비스의 가장 강력한 논거입니다.

| 항목 | 기한 |
|---|---|
| 상속포기·한정승인 결정 | 상속 개시 인지일로부터 **3개월** |
| 금융재산 조회 결과 통보 | 신청 후 **최대 20영업일** |
| 조회 결과 확인 가능 기간 | 접수일로부터 3개월, 이후 삭제 |
| 상속세 신고 | 6개월 |

**빚이 얼마인지 알기 위한 조회에만 한 달이 걸리는데, 상속포기 결정은 3개월 안에 해야 합니다.**

기한을 넘기면 단순승인으로 간주되어 부채까지 전부 승계됩니다. 사후 구제 수단(특별한정승인, 민법 제1019조 제3항)이 존재하지만 '중대한 과실 없이 채무 초과 사실을 몰랐음'을 입증해야 하는 예외적 절차입니다. 그리고 정부 조회 서비스는 이 3개월 기한을 알려주지 않습니다.

### 2.4 문제의 공신력

- 국민권익위원회, 「상속 금융재산 통합지급서비스 도입 방안」 금융감독원장 권고 (2026.6)
- 청와대 비서관실 참여, 내년 초 시범 운영 예정
- 국민신문고 민원: 기관마다 요구 서류·양식·절차가 모두 달라 복잡하다는 호소 다수
- 재산이 흩어져 있으면 최대 10여 곳의 금융회사를 직접 방문해야 하는 실태

**문제의 존재를 정부가 공식 인정했습니다.**

## 4. 솔루션

### 4.1 핵심 컨셉

**AI 상담사가 아니라, 3개월짜리 마감을 대신 지켜주는 관제탑.**

챗봇이 아닙니다. 대시보드입니다. 사용자가 물어보기를 기다리지 않고, 기한이 다가오면 먼저 알립니다.

### 4.2 사용 흐름

```
1. 사망일 입력          → 전체 기한 타임라인 즉시 생성
2. 서류 업로드          → 가족관계증명서, 안심상속 조회 결과
3. AI 구조화            → 상속인 구성 · 법정상속분 · 기관별 재산
4. 실행 계획 생성       → 기관별 필요서류 · 방문 순서 · 서류 합산
5. 누락 탐지            → 사용자가 묻지 않은 것을 역으로 알림
6. 지속 추적            → 진행률 관리 · 기한 임박 알림
```

### 4.3 핵심 기능

**기능 1 — 기한 관제**

사망일 하나만 입력하면 모든 기한이 D-day로 환산됩니다.
(예시 — 사망일 2026-07-20, 기준일 2026-08-13, 인지일=사망일 가정)

```
D-68   상속포기·한정승인 결정 마감 (2026-10-20)
D-171  상속세 신고 마감 (2027-01-31)
D-171  취득세 신고 마감 (부동산 등 보유 시)
D-352  안심상속 원스톱 신청 마감 (2027-07-31)
```

조회 신청 전이라면 경고합니다.
> "금융재산 조회는 결과까지 최대 20영업일 걸립니다. 지금 신청해도 결과는 약 D-39에야 도착합니다."

**기능 2 — 문서 기반 상황 재구성**

사용자에게 묻지 않고 문서에서 추출합니다.

| 업로드 | 추출 |
|---|---|
| 가족관계증명서 | 상속인 구성, 법정상속분 |
| 안심상속 조회 결과 | 기관별 재산·부채 목록 |
| 사망진단서 | 상속개시일 확정 |
| 보험증권 | 담보별 청구 가능 항목 |

**기능 3 — 기관별 실행 계획**

정부 조회 결과는 이렇게 생겼습니다.
```
A은행 · 예금 있음
B생명 · 가입 사실 있음
```

이음은 이렇게 바꿉니다.
```
A은행 — 이번 주 방문
필요서류: 기본증명서, 가족관계증명서, 상속인 전원 인감증명서
상속인 전원 동의 필요 · 동행 또는 위임장
비대면 위임장 제출 가능 (해당 은행 앱)
예상 소요: 1회 방문
```

**서류 합산 기능**이 포함됩니다.
> "가족관계증명서 6통, 기본증명서 4통을 한 번에 발급받으세요. 기관마다 원본을 요구합니다."

주민센터 방문을 6회에서 1회로 줄입니다.

**기능 4 — 누락 탐지**

질의응답이 아니라 능동 탐지입니다. 규정 DB와 사용자 상황을 교차 대조해 "해당되는데 아직 안 한 것"을 찾아냅니다.

```
⚠ 보험 3건 중 2건이 사망 시 지급 담보를 포함할 가능성이 있습니다.
  조회 결과에는 가입 사실만 표시되므로 각 사에 직접 확인이 필요합니다.

⚠ 예금 합계가 300만 원 이하입니다.
  KB국민은행은 이 경우 상속인 1인 단독 청구가 가능합니다.
  전원 방문이 불필요할 수 있습니다.

⚠ 부채 합계가 예금 합계를 초과합니다.
  한정승인 검토가 필요할 수 있습니다. 결정 기한 D-69.
  이 판단은 법률 전문가 상담이 필요합니다.
```

마지막 항목에 주목하십시오. **"검토가 필요할 수 있습니다 + 기한 + 전문가"에서 정확히 멈춥니다.** 법률 판단을 하지 않습니다.

## 5. AI 활용

### 5.1 설계 원칙 — 결정론과 확률론의 분리

금융 절차에서 날짜를 틀리면 회복이 불가능합니다. 환각이 허용되지 않는 영역은 규칙 엔진으로 처리했습니다.

**AI를 쓰지 않은 영역 (규칙 엔진)**
- 기한 계산 — 날짜 산술
- 법정상속분 — 민법 조문 적용
- 진행 상태 관리 — DB

**AI를 쓴 영역 (LLM)**

| 기능 | 필연성 |
|---|---|
| 문서 이해 | 기관마다 양식·레이아웃이 달라 정규식 파싱 불가. VLM으로 의미 단위 추출 |
| 관계 추론 | 증명서에는 "상속인"이라 적혀 있지 않음. 부·모·배우자·자녀 관계에서 상속 순위 추론 (대습상속, 재혼, 양자 등 예외 다수) |
| 규정 대조 | 기관별 규정이 비정형 문서. 사용자 상황과 교차 대조해 해당 항목만 추출 (RAG + 추론) |
| 언어 생성 | "피상속인의 금융채권 존부" → "아버지 명의로 남은 예금이 있는지". 고령 사용자 대응 |

### 5.2 이 설계가 주는 방어력

주최기관이 금융보안원입니다. **신뢰성을 위해 AI 사용 범위를 의도적으로 제한한 설계**는 감점이 아니라 가점 요소입니다.

### 6.1 경쟁 지형

| 대상 | 커버 범위 | 이음과의 관계 |
|---|---|---|
| 안심상속 원스톱 | 재산 조회 | **전제 조건** — 결과를 입력으로 사용 |
| 금감원 조회 서비스 | 금융거래 유무 | **전제 조건** — 결과를 입력으로 사용 |
| 정부 통합지급서비스 (예정) | 서류 제출 표준화 | 보완 — 지급 절차만 해결 |
| 도와줘상속 등 | 상속세 신고, 소송 대행 | 시장 분리 — 상위 6% 대상 |
| 헬프미 | 상속포기 전자소송 | 시장 분리 — 유상 수임 |
| 범용 LLM 챗봇 | 질문 시 답변 | **대체 불가 영역 존재** (아래) |

### 6.2 "그냥 챗봇에 물어보면 되지 않나"에 대한 답

이 질문은 심사에서 반드시 나옵니다. 정면으로 답합니다.

**챗봇은 물어봐야 답합니다. 상속에서 사람이 실패하는 건 답을 못 들어서가 아니라 물어보는 걸 잊어서입니다.**

| 근거 | 설명 |
|---|---|
| 시간축 | 상속은 3개월 프로세스. 대화는 휘발됨. D-69가 D-7이 되는 동안 아무도 알려주지 않음 |
| 정확성 | 변호사 운영 블로그조차 안심상속 신청 기한을 6개월(구 기준)로 잘못 안내 중. 검증된 규정 DB + 출처 표시가 필요 |
| 공동 진행 | 상속인 3명이 함께 진행. 개인 대화는 상태 공유 불가 |
| 접근성 | 고령 상속인은 프롬프트를 작성하지 못함. 빈 대화창과 정해진 입력 항목은 난이도가 다름 |

### 6.3 데이터 진입장벽

금융권 사이트 상당수가 자동 접근(robots.txt)을 차단합니다. 기관별 상속 절차 규정을 구조화한 데이터셋이 시장에 없는 이유입니다.

이음은 금감원·9개 협회의 「상속인 표준 제출서류」를 기준선으로 삼고, 기관별 예외(델타)를 구조화합니다. **이 델타가 소비자가 영업점에서 헛걸음하는 이유이고, 서비스의 자산입니다.**

## 7. 구현 계획

### 7.1 3주 일정

| 주차 | 작업 |
|---|---|
| 1주 | 규정 DB 수집(6개 기관) · 기한 엔진 · 법정상속분 엔진 |
| 2주 | 문서 파싱 · 누락 탐지 로직 · 대시보드 UI |
| 3주 | 시나리오 30~50건 검증 · 정확도 측정 · 발표 준비 |

### 7.2 기술적 실현 가능성 근거

- **실시간 데이터 불필요** — 크롤링, 마이데이터 연동, 외부 API 실시간 연계 없음
- **모델 학습 불필요** — 상용 LLM API + 프롬프트 + RAG로 해결. GPU 불요
- **부분 실패 허용** — 문서 파싱 실패 시 수동 입력으로 대체. 기관 3곳만 있어도 데모 가능

### 7.3 대상 기관 (MVP)

| 업권 | 기관 |
|---|---|
| 은행 | KB국민, 하나, 신한, 카카오뱅크 |
| 보험 | 삼성생명 |
| 증권 | 유안타증권 |

6개 기관 수집 완료 — 5곳 통화 검증(`call_verified`), 카카오뱅크는 기관 정책상 통화 불가로 원문 확인(`source_confirmed`) 상태이며 데모 시나리오에서 제외합니다. 상세: `docs/04_규정데이터_수집결과.md`

### 7.4 기관 확장 비용

6개는 시간 제약이지 기술 제약이 아닙니다. 금감원·9개 협회의 「상속인 표준 제출서류」가 공통 기준선으로 존재하므로, 규정 DB는 **공통 표준 + 기관별 델타** 구조입니다.

기관별 델타는 소액 간소화 기준, 서류 유효기간, 비대면 채널, 연락처 등 **필드 5~6개** 수준입니다. 기관 1곳 추가는 원문 확인 20~30분 + 고객센터 검증 통화 5~10분이며, 확장 비용은 선형이 아닙니다.

발표 시 프레이밍: **"실제 검증한 6개 기관(5곳 통화 검증)"이 "미검증 20개"보다 신뢰도가 높습니다.** 전 기관 수용은 데이터 신뢰성 검증 시간의 문제일 뿐 구조적 장벽이 없습니다.

## 8. 검증 계획

정량 지표를 제시합니다. "LLM 래퍼"라는 인상을 지우는 가장 효율적인 투자입니다.

**측정 방법**
1. 실제 상속 유형을 반영한 시나리오 30~50건 구성
2. 각 시나리오의 정답 액션 리스트를 사전 작성
3. 서비스가 탐지한 항목과 대조

**지표**
- 누락 탐지 재현율 — 놓치면 안 되는 항목 중 잡아낸 비율
- 오탐율 — 해당 없는데 제시한 비율
- 문서 파싱 정확도 — 상속인 구성 추출 정확도

**목표: 재현율 85% 이상**

## 10. 지속 가능성 및 확장성

### 10.1 공공성 우선

이 서비스는 수익 모델을 전면에 세우지 않습니다. 이는 약점이 아니라 **존재 이유**입니다.

상속인 대다수(비과세 94%)는 전문가 수수료를 지불할 수 없거나 지불할 이유가 없는 구간에 있습니다. 시장이 형성되지 않아 비어 있는 영역이며, 그래서 이 서비스가 필요합니다. 수익성을 강조하는 순간 이 논리가 스스로 무너집니다.

공모전 취지(금융 현안 해결, 포용적 금융서비스)와도 이 방향이 정합합니다.

### 10.2 지속 가능성

장기 운영 방안으로는 금융사 제휴를 상정합니다.

근거는 접점입니다. **상속 절차는 금융사가 상속인(자녀 세대)을 대면하는 사실상 유일한 순간입니다.** 평소 접근할 수 없는 40~50대가 서류를 들고 영업점을 직접 찾아오며, 이 경험의 품질이 신규 고객 관계 형성 여부를 가릅니다. 절차 지원 도구에 대한 금융사 수요는 여기서 발생합니다.

### 10.3 주최사 접점

| 주최사 | 접점 |
|---|---|
| 하나은행 · 신한은행 · 카카오뱅크 | 상속예금 지급 절차 |
| 생명보험협회 | 사망보험금 청구 |
| KB증권 | 계좌 승계 |
| 금융보안원 | 신뢰 가능한 AI 설계 사례 |

**은행·보험·증권이 모두 걸리는 몇 안 되는 영역입니다.**

### 10.4 확장 방향

동일 엔진으로 다른 생애 저빈도 금융 사건에 적용 가능합니다.
- 부모 요양 진입 시 금융 정리
- 실직·폐업 시 금융 정리

공통 구조: 복잡한 절차 + 촘촘한 기한 + 놓치면 회복 불가.
